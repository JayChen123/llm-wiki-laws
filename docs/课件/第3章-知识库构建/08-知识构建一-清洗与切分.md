# 3.1 知识构建（一）—— 清洗与"编→章→节→条"切分

> 定位：摄入期第一步，把脏兮兮的 PDF 变成 **1465 个法条级知识点**。这一节坑最多，也最能体现"编译"的含金量。

本节目标：

1. 看懂摄入管线 `pipeline.py` 的完整流程；
2. 掌握法律 PDF 的清洗要点（页眉日期 / 页码 / 裸域名 / 康熙部首变体 / 折行）；
3. 吃透"**编→章→节→条**"两阶段状态机切分，以及三个最易错的判别点；
4. 理解为什么 `CN_NUM_CHARS` 必须含"零"和"千"——一次字符集疏漏让民法典丢掉 261 条。

## 1. 摄入管线全景（`pipeline.py`）

```
data/src/*.pdf ──markitdown（增量：raw 里缺 md 才转）──► data/raw/*.md
                                                            │
                          discover → convert → collect_points│
                                                            ▼
                            逐份 md 提取知识点 → 合并后**全局统一编号** KP_001…
                                                            │
                                    concept_map.enrich_keywords()（概念关键词增强）
                                                            │
                                    bge-m3 语义向量（**只编码一次**）
                                                            │
                    ┌───────────────────────────────────────┼──────────────────────┐
                    ▼                                       ▼                      ▼
        knowledge_graph.json（权威源）           Milvus llm_wiki_laws        wiki/ 人读视图
                    │
                    └─► Neo4j（sync_from_json）
```

```python
# pipeline.py（要点节选）
def run_pipeline(...):
    convert_pdf_to_md()                      # PDF → MD：增量，已存在则跳过
    points = collect_points()                # 提取 + 全局重编号 + 概念增强
    vectors = embedder.encode([semantic_text(p) for p in points])   # 只编码一次
    graph = build_graph(points, vectors=vectors)                    # 复用向量建语义边
    save_graph(graph, GRAPH_PATH)            # 权威源先落盘
    sync_from_json(GRAPH_PATH)               # 再同步派生副本（失败即报错）
    store.upsert(graph["nodes"], vectors)    # 写 Milvus（全量对齐）
    write_wiki(points, graph)                # 人读视图
```

两个设计点值得注意：

- **向量只算一次**：`semantic_text()` 的编码结果同时用于（a）图谱的语义边、（b）写 Milvus。分开算两次不仅慢，更危险——两处语义不一致会让"图谱邻居"与"向量召回"对不上。
- **失败策略**：json 落盘之后，Milvus 与 Neo4j 两个派生副本**任一失败都直接抛错**，不静默跳过。理由很直白：构建结果已经在 json 里了，不会丢；但如果悄悄跳过，就会出现"json 已更新、副本还是旧数据"的静默不一致。

## 2. PDF → Markdown：转换产物的"脏"

用微软 markitdown 把 PDF 转成 markdown，产物**不能直接切分**，它带着一整页 PDF 版式的残留：

| 噪音 | 长相 |
|---|---|
| 页眉日期 | `2024/11/15`、`8/23/2020`（**两种写法都要挡**） |
| 孤立页码 | 单独成行的数字 |
| 网址 | `https://www.npc.gov.cn/...`、**裸域名 `www.`**（没有协议头的那一类最容易被漏掉） |
| 目录点线 | `第二章　促进就业..........5` |
| 网页脚注 | 站名、栏目名等 |

为什么必须清掉？因为这些噪音行**会被"章/节"上下文吸附**——它们出现在某一章标题之后，就被挂到那一章下面，`flush()` 时生成一个 `clause` 为空的知识点。历史上曾因此产出 **34 个垃圾知识点**（页眉噪音单独成点）。

兜底手段是 `flush()` 要求 `clause` 非空：

```python
def flush():
    if clause:                # 章/节标题不产生知识点
        points.append(KnowledgePoint(...))
```

## 3. 清洗四件套（`knowledge_extract.py`）

### 3.1 噪音行过滤

```python
_URL_RE = re.compile(r"^(?:https?://|www\.)")     # 含裸域名
if _DATE_RE.match(row) or _PAGE_MARKER_RE.match(row) or _URL_RE.match(row):
    continue
```

### 3.2 康熙部首变体归一（法律 PDF 特有的坑）

法律 PDF 的文本里，"第一条"可能根本不是"第一条"——而是用**康熙部首变体**拼出来的：`第⼀条`（`⼀` 是 U+2F00 KANGXI RADICAL ONE，不是汉字"一"）。这类字符用眼睛看几乎一样，正则却完全匹配不上，**结果是一条法条都切不出来**。

处理办法：匹配前先对整行做一次 `translate`，用 NFKC 归一 + 手工映射补齐 NFKC 覆盖不到的几个：

```python
_KANGXI_TABLE = str.maketrans({
    ...      # NFKC 归一为主
    "⺠": "民", "⻅": "见", "⻓": "长", "⻔": "门",   # NFKC 漏网的几个（U+2E80 区间）
})
```

### 3.3 合并被 PDF 折行的两行

PDF 转出来的正文经常把一条法条**折断成两行**（版式宽度所限）。若不做合并，后半句会变成"孤立正文"，既污染上下文又可能被误判成新条。规则是：当前行不是任何结构边界（编/章/节/条），就把它并进上一条正文。

### 3.4 换页符 `\f` 与"行号漂移"

这是最容易忽略、后果又最实际的一条：源 markdown 里含**换页符 `\f`**（民法典约 130 处）。如果按 Python 惯例用 `splitlines()` 拆行，`\f` 也会被当成换行——于是**行号比编辑器里看到的行号大**（民法典末尾累计偏移 129 行）。

后果：知识点里记录的 `source: 中华人民共和国民法典.md L9475-9489` 这种"原文位置"**对不上**，引用溯源直接失效。

现方案是按**物理行**算：

```python
# 按物理行（仅 \n）拆分：splitlines() 会把换页符 \f 也当换行
for lineno, raw_line in enumerate(text.split("\n"), start=1):
    for seg in raw_line.split("\f"):        # 行内再按 \f 分段，**共用同一行号**
        ...
```

## 4. "编→章→节→条"切分：两阶段状态机

### 4.1 四个边界正则（都锚定行首、都要求后跟空白）

```python
CN_NUM_CHARS = "一二三四五六七八九十百千零"

_PART_RE    = re.compile(rf"^第([{CN_NUM_CHARS}]+)编[　\s]+(.+)$")
_SUBPART_RE = re.compile(rf"^第([{CN_NUM_CHARS}]+)分编[　\s]+(.+)$")
_CHAPTER_RE = re.compile(rf"^第([{CN_NUM_CHARS}]+)章[　\s]+(.+)$")
_SECTION_RE = re.compile(rf"^第([{CN_NUM_CHARS}]+)节[　\s]+(.+)$")
_ARTICLE_RE = re.compile(rf"^第([{CN_NUM_CHARS}]+)条[　\s]+(.*)$")
```

### 4.2 两阶段状态机

```
阶段一：正文首个"第X条"出现之前  ── 视为「目录 / 元数据」
        · 只更新 编/章/节 上下文
        · 内容行一律丢弃（目录点线就在这里被丢掉）

阶段二：从首个"第X条"开始  ── 视为「正文」
        · 遇到新条 → flush 上一条、开新条
        · 普通行 → 并入当前条正文
        · 表格块 → 回填进当前条
```

### 4.3 三个关键判别点（面试最常追问）

| 判别点 | 做法 | 不这么做会怎样 |
|---|---|---|
| 条文头必须"第X条"**后跟空白** | `_ARTICLE_RE` 要求 `[　\s]+` | 正文里的**交叉引用**"第三十九条和第四十条…"条后无空白，会被误当成新条头，导致重复编号 |
| **"编"是必需层级** | `part` / `part_title` 参与分组与标题 | 民法典 7 编各自从"第一章"重新起算，不看编就会把不同编的同号章并成一团（详见 3.2） |
| **"分编"只作结构边界** | `_SUBPART_RE` 命中后**只重置章上下文** | 分编标题既不产生知识点、也不能并进上一条正文——曾污染 6 条条文正文 |

另外注意 `_PART_RE` 用 `^` **锚定行首**：这样正文里的"依照本法第一编第六章…"不会被误判成编标题。

## 5. 中文数字字符集：一个字符丢掉 261 条

`CN_NUM_CHARS` 的完整取值是：

```python
CN_NUM_CHARS = "一二三四五六七八九十百千零"
```

它必须同时含 **"零"** 和 **"千"**：

- 缺"零" → `第一百零一条` 匹配不上；
- 缺"千" → `第一千二百六十条` 匹配不上。而民法典的条号**跨过 1000**，于是从"第一千条"开始**整段漏切**——实测只抽到 **999/1260** 条，整整丢掉婚姻家庭编、继承编、侵权责任编等 **261 条**。

更需要注意的是：这个常量**不止用在一处**。它同时被 `cn_to_int()`（中文数字转整数）、交叉引用正则（`graph_build.py` 识别正文里的"第X条"）、关键词清洗正则使用——**改一处要一起改**，否则会出现"切分正常但交叉引用建不出边"这种更难查的问题。

> 这类 bug 的特点是：**不报错、只少数据**。所以收数验证（下一节）不是形式主义。

## 6. `KnowledgePoint` 结构与"一条一知识点"

```python
@dataclass
class KnowledgePoint:
    id: str                  # 全局唯一，KP_001…
    title: str               # 如"第四章·第四十七条"；有编的法律为"第二编 物权·第二章·第十三条"
    chapter: str             # 章节号，如"第五章"
    chapter_title: str       # 章节标题
    part: str = ""           # 编号，如"第二编"（无编的法律为空）
    part_title: str = ""     # 编标题，如"物权"
    clause: str = ""         # 条文，如"第五十七条"（节内为"第X节 节名·第X条"）
    content: str = ""        # 清洗后的正文
    keywords: list = ...     # jieba TF-IDF + 编/章节/条文主题词 + 概念增强
    source: str = ""         # 来源与行号，如"中华人民共和国劳动合同法.md L31-34"
```

粒度就是一句话：**一条法条一个知识点**，而不是定长 chunk。`title` 里带编名（如"第二编 物权·第二章·第十三条"）不是装饰——它让"编名参与 BM25 索引与语义编码"，使"物权"这类编级语义也能参与召回。

## 7. 收数验证：1465 = 1260 + 107 + 98

多份文档提取完成后会**合并并全局统一编号**，编号按文档顺序连续分配：

| 法律 | 条数 | 编号区间 |
|---|---|---|
| 中华人民共和国劳动合同法 | 98 | `KP_001` – `KP_098` |
| 中华人民共和国劳动法 | 107 | `KP_099` – `KP_205` |
| 中华人民共和国民法典 | 1260 | `KP_206` – `KP_1465` |
| **合计** | **1465** | — |

> 这里有个对评估很关键的性质：**民法典排在 `KP_206` 之后**，所以两部劳动法的编号映射（`KP_001`–`KP_205`）在新增民法典后**保持不变**——历史 recall 基线因此仍然可比。这不是巧合，是刻意让"新增文档追加在末尾"。

收数验证之所以必做：前面几个坑（缺"千"、章标题成点、交叉引用误切）**全都不抛异常**，唯一的表现就是"数量不对"。先看总数对不对，再抽样看内容对不对，是最省时间的排查顺序。

## 8. 本节小结

- 摄入管线是**增量 + 幂等全量重建**：PDF→MD 增量，MD→知识点→图谱→落盘为全量；派生副本写入失败**显式报错**，不静默跳过。
- 清洗要挡住五类噪音，其中**裸域名 `www.`** 和**两种日期写法**最容易漏；`flush()` 要求 `clause` 非空是挡住"噪音生成垃圾知识点"的最后一道闸。
- **康熙部首变体**必须归一（`⼀` ≠ `一`），否则一条都切不出来。
- 行号按**物理行**算（`\n` 拆行、行内按 `\f` 分段共用行号），否则溯源行号整体偏移。
- 切分是**两阶段状态机**，三个判别点：条头要求后跟空白、**"编"是必需层级**、"分编"只作结构边界。
- `CN_NUM_CHARS` 必须含"零"和"千"，且被三个模块共用——缺"千"曾让民法典丢掉 261 条。

## 企业常见面试问答

**Q1：PDF 解析最难的地方是什么？**

> 不是解析本身，是**噪音与结构的边界**。PDF 里的页眉、页码、目录点线、折行，在文本层面和正文长得一样；而法律文档的结构靠"第X编/章/节/条"这几个词区分，这几个词又会在正文里作为交叉引用出现（"第三十九条和第四十条…"）。所以难点是**用最小的规则把"结构行"和"内容行"分开**：我们用"条头必须后跟空白"+"编/章/节标题不产生知识点"+"分编只重置上下文"三条规则解决，而不是上一个复杂的 NLP 模型。规则可解释、可测试，是这类工程的首选。

**Q2：怎么保证切分不出错？**

> 三层：① **收数验证**——1465 = 1260 + 107 + 98，数量不对立刻能发现；② **单元测试锁边界**——千位条号、编层级与同号章、分编边界、康熙部首、`\f` 行号各有专测；③ **抽样核对**——随机挑几条知识点，比对 `content` 与原文，并检查 `source` 行号能否定位回去。核心认知是：**这类 bug 不抛异常、只少数据或错位**，所以验证必须主动做。

**Q3：为什么不用大模型直接把 PDF 转成结构化知识点？**

> 三个原因：① **不可审计**——模型抽出来的条文如果错了，你很难判断错在哪一步，而规则化的切分可以逐条比对原文；② **成本与稳定性**——1260 条法条每次都过一遍大模型，既慢又不可复现，同一份 PDF 两次跑出来还可能不一样；③ **这个任务的本质是版式与字符问题，不是语义问题**。"第X条"的识别、康熙部首的归一、行号的对应，都是确定性的字符工程，用确定性方法解是最优的。大模型该用在**查询期**（判断意图、决定补取哪条、综合生成），而不是摄入期做确定性抽取。

**Q4：新增一部法律要改多少东西？**

> 理想情况是**零改代码**：把 PDF 丢进 `data/src/`，重跑 pipeline 就自动并入（PDF→MD 增量、知识点合并重编号、图谱与 Wiki 重建、向量全量重写、同步 Neo4j）。但有两处需要先确认：① 新法律若有**"编/分编"层级或千位条号**，要确认 `CN_NUM_CHARS` / `_PART_RE` / `_SUBPART_RE` 覆盖得住；② 想让它的概念出现在"核心概念导航"里，要在 `ingest/concept_map.py` 补映射。另外 `generation/intent.py` 的 `COVERED_LAWS` 也要同步——否则新法律的问题会被意图分类器判成"本库未覆盖"而拒答。
