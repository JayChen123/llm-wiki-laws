## 1. 一句话定位与四条链路

一句话：**摄入时把三部法律"编译"成法条级知识点 + 关联图谱，查询时只做"定位 + 综合"，并带上用户记忆与可扩展的 Web 服务。**

代码按**阶段**分层放在 `app/` 下，一条链路一个目录：

| 链路 | 目录 | 何时跑 | 一句话 |
|---|---|---|---|
| ① 摄入 Ingest | `app/ingest/` | 离线，数据变更后重跑（幂等） | PDF/md → 知识点 → 图谱 → 落盘与同步副本 |
| ② 检索 Retrieval | `app/retrieval/` | 每次提问 | 双路召回 → RRF → 图谱多跳 → 反思补取 |
| ③ 生成 Generation | `app/generation/` | 每次提问 | 意图路由 + qwen-max 综合生成（带引用） |
| ④ 记忆 Memory | `app/memory/` | 每次提问 | 短期会话 + 画像 + 长期语义索引 |
| ⑤ 服务化 API | `app/api/` | 常驻 | 认证 + 会话 CRUD + SSE 问答 + 托管前端 |

两个入口——**Web**（`app/api/`）与 **CLI**（`app/cli.py`）——共用同一条问答链路（`app/kb.py`），区别只在"用户身份从哪来"。

```
浏览器(React) ──HTTP+SSE──► FastAPI ──┐
                                      ├──► app/kb.py ──► 同一条问答链路
CLI(uv run app.cli) ──────────────────┘
```

## 2. 两阶段架构总览

**摄入**（离线、幂等全量重建）：

```
data/src/*.pdf ──markitdown(增量)──► data/raw/*.md
data/raw/*.md ──编/章/节/条切分──► KnowledgePoint[]（1465，全局编号 KP_001…）
  ├─► concept_map 概念关键词增强（53 个概念：加班费 → 劳动法第四十四条 …）
  ├─► bge-m3 语义向量（只编码一次：既供语义边、也写 Milvus）
  ├─► 关联图谱 knowledge_graph.json（权威源，21252 边）
  │      └─► 同步 ──► Neo4j 图数据库（应用检索时从这里读图）
  ├─► 向量 ──► Milvus 集合 llm_wiki_laws（dim 1024 · HNSW+COSINE）
  └─► wiki/ 人读视图（index 概念导航 + log + 少量示例页）
```

**查询**（在线，每次提问）：

```
用户问题 → 意图识别（可答/未覆盖/无关）
  ├─ 非"可答"：兜底话术（不检索不生成），仍写记忆与日志
  └─ "可答" → 短期记忆按需注入检索词
       → BM25 关键词 + bge-m3 向量（Milvus）双路召回
       → RRF 融合 → Top-K 种子（10）
       → 图谱多跳扩展（≤3 跳，crossref 权重 1.5）
       → 反思循环（≤3 轮，沿引用补取）
       → 长期记忆召回（强制 user_id 过滤）
       → qwen-max 流式生成（标题带法律名 + 列出引用）
       → 写 MySQL messages + Milvus 用户记忆 + logs/qa.log
```

**存储分工**（这一格最关键，务必记牢）：

```
Neo4j  图数据库（查询副本）：节点 + 四类关系 SIBLING/KEYWORD/SEMANTIC/CROSSREF
Milvus 向量（非知识载体）：llm_wiki_laws 法律向量 │ llm_wiki_user_memory 用户记忆
MySQL  记忆唯一后端：users · sessions · messages(含 citations) · user_profile
文件   权威源（人读/可审计/可 git diff）：knowledge_graph.json │ wiki/ 人读视图
```

> ⚠️ 一句话记住分工：**权威源只有 `knowledge_graph.json`**。Neo4j 与 Milvus 都是它的**派生副本**，`wiki/` 是给人看的**视图**（不参与检索）。副本与权威源不一致时，永远以 json 为准并重跑同步。

## 3. 技术选型逐一说清

| 环节 | 候选 | 本项目选择 | 理由 | 代价 |
|---|---|---|---|---|
| 知识载体 | 向量库 / 文件+图库 | **JSON 图谱（权威源）** | 可读、可审计、可 git diff | 需自己维护"权威源 → 副本"的同步 |
| 图查询 | 只留 JSON / Neo4j | **Neo4j 副本** | 引用链遍历（`-[:CROSSREF*1..3]->`）是图库强项；JSON 每次要全图读进内存 | 多一个要运维的服务 |
| 向量召回 | `.npy` 文件 / Milvus | **Milvus** | 有"集合"语义、支持主键对齐与删除；文件缓存只按"存在与否"判定，会静默失效（3.4 细讲） | 多一个服务；客户端版本有硬约束 |
| 记忆 | SQLite / MySQL | **MySQL（唯一后端）** | 多用户隔离、与 Web 端一致；SQLite 降级路径曾因漏 `user_id` 过滤导致画像跨用户泄漏 | 本地开发要多起一个容器 |
| Web | Flask/Django / FastAPI | **FastAPI** | 原生 async，SSE 流式与依赖注入（`Depends`）都顺手，接口测试可完全离线 | — |
| 前端 | 独立部署 / 同源托管 | **Vite 构建 + FastAPI 同源托管** | 免 CORS/CSRF 配置，Cookie 认证最省心 | 需先 `npm run build` |
| 向量模型 | API / 本地 | **本地 bge-m3** | 零 API 成本、离线可用；语义边与查询共用同一模型 | 2.2GB 模型，首次加载慢 |
| 生成模型 | 小模型 / 大模型 | **qwen-max** | 法律领域长上下文综合需要能力上限 | 成本与延迟；分类/反思改用 qwen-turbo 降本 |

> 选型有一条暗线：**凡是"会因为静默失败而毁掉可信度"的地方，宁可多一个依赖也要显式失败**。所以 Milvus 写入失败直接抛错、MySQL 连不上直接报错、Neo4j 不可用即报错——都不做"悄悄降级"。

## 5. 配置：唯一配置源与凭证集中

### 5.1 `app/config.py` 是唯一配置源

⚠️ 先说一个**已被历史文档写错、必须纠正**的点：早期文档描述的"根目录 `config.py` 由用户维护 + `app/config.py` 复用"**已经不成立**——根 `config.py` 早已不存在，配置只有 `app/config.py` 一处。看到旧说法请直接忽略。

`app/config.py` 里分四类：

| 类别 | 代表项 |
|---|---|
| 路径常量 | `SRC_DIR` / `RAW_DIR` / `WIKI_DIR` / `CONCEPTS_DIR` / `GRAPH_PATH` |
| 模型与 LLM | `BGE_MODEL_PATH`（**机器相关，换环境先改这里**）/ `LLM_MODEL` / `DASHSCOPE_API_KEY` |
| 服务连接 | `MILVUS_*` / `MYSQL_*` / `NEO4J_*` / `JWT_SECRET` |
| 检索与多跳 | `TOP_K` / `EXPAND_K` / `EXPAND_HOPS` / `EXPAND_DECAY` / `RETRIEVAL_MODE` / 意图与反思参数 |

**除路径与模型路径外，都能用环境变量覆盖**——这样 A/B 调参（比如 `EXPAND_K=3` vs `5`）不用改代码。

### 5.2 服务凭证集中在 `docker/.env`

compose 与应用**读同一份**凭证文件，改一处即可让两边一致：

```bash
cd docker && cp .env.example .env   # 填 MySQL / Neo4j / Redis / MinIO 的账号密码 + JWT_SECRET
```

应用侧用 `python-dotenv` 读取，三个刻意的开关：

| 参数 | 值 | 为什么 |
|---|---|---|
| `override` | `False` | **不覆盖已有环境变量**——真实环境变量优先，容器化/CI 里可继续用导出变量覆盖 |
| `interpolate` | `False` | 不展开 `$`——避免密码里的 `$` 被悄悄改写 |
| 文件 | 不入库 | `.gitignore` 已忽略 `.env`，模板是 `.env.example` |

> 踩坑提示：密码里应**避免 `$`**。compose 会把它当变量语法（需写 `$$` 转义），而 dotenv 按字面读取、不还原——两边行为不一致，最容易出"compose 能连、应用连不上"的怪问题。

| 约束 | 说明 |

## 7. 代码走读：`kb.load()` —— 一个函数看懂全项目接线

如果说要挑一个函数来代表整个系统的"工程结构"，那就是 `KnowledgeBase.load()`：它把摄入产物、图库、向量库、检索器全部接起来，并且在**接线处**集中体现了本项目的几条铁律。

```python
@classmethod
def load(cls, embedder=None, store=None) -> "KnowledgeBase":
    # ① 图谱从 Neo4j 读。不做降级：Neo4j 不可用即报错，
    #    避免"以为在用图数据库、实际读了本地文件"。
    #    注意变量名不要用 store —— 那个名字留给下面注入的 Milvus 向量库
    graph_store = Neo4jGraphStore()
    try:
        graph = graph_store.load()
    finally:
        graph_store.close()

    if not graph["nodes"]:
        raise RuntimeError("Neo4j 里没有知识点：请先运行 "
                           "`uv run python -m app.ingest.sync_graph` 同步图谱")

    nodes = graph["nodes"]
    if embedder is None:
        embedder = Embedder()

    kw = KeywordRetriever(nodes)                    # 关键词路：永远可用
    vec = None
    try:
        store = store if store is not None else MilvusVectorStore()
        store.count()                               # ② 探活：不可达会在此抛出
        vec = VectorRetriever(nodes, store, embedder)
    except Exception as exc:                        # 向量库不可用 → 退化为纯关键词
        print(f"[kb] Milvus 向量库不可用（{exc}），退化为纯关键词检索")

    # ③ 必须显式传入扩展参数！构造函数有默认值（expand_k=3），
    #    不传会让 config 里的 EXPAND_K 静默失效
    hybrid = HybridRetriever(nodes, graph, kw, vec, expand_k=EXPAND_K,
                             expand_hops=EXPAND_HOPS, expand_decay=EXPAND_DECAY)
    retriever = hybrid
    if RETRIEVAL_MODE == "reflect":
        try:
            retriever = ReflectiveRetriever(nodes, graph, hybrid, Reflector(),
                                            max_rounds=REFLECT_MAX_ROUNDS)
        except Exception as exc:                    # 反思初始化失败 → 回退图谱扩展
            print(f"[kb] 反思式检索初始化失败（{exc}），回退为图谱多跳扩展")
```

### 7.1 这 40 行里的信息量

| 位置 | 体现的原则 | 换个写法会怎样 |
|---|---|---|
| **① 图谱报错不降级** | 一致性问题不让步（3.4） | 静默读本地文件 → "以为在用图库"的不可控状态 |
| `finally: graph_store.close()` | 资源释放写在 `finally` | 异常时连接不关，长期跑会耗尽连接 |
| **② `store.count()` 探活** | 不靠"新建对象"判断可用性 | Milvus 只是"对象能建出来"但服务不可达 → 直到真检索才崩 |
| **向量库失败只警告** | 可用性问题上可以软（4.2） | 直接抛错 → 整条问答链路不可用，而关键词路本来能答 |
| **③ 显式传 `expand_*`** | 配置项必须真的接线（3.3/6.1） | 参数静默失效，扩展规模长期是 3 而不是 5 |
| **变量名不叫 `store`** | 命名要为"注入"让路 | 图存储覆盖了向量库的注入参数 → 测试注入失效（曾踩过） |
| 反思失败回退 bfs | 增强失败不该拖垮主干 | 整条链路不可用，而基础扩展本来够用 |

### 7.2 一条值得记住的经验

这个函数里出现过两个**同类 bug**，都值得记住：

1. **变量名冲突**：曾用 `store = Neo4jGraphStore()` 覆盖了 `load(store=...)` 这个**注入 Milvus 向量库的参数**，导致测试注入失效（`test_kb` 抓到）。**参数名是接口的一部分，别在函数体里复用。**
2. **参数漏传**：`expand_k/expand_hops/expand_decay` 曾没传下去（见上）。**"构造函数有默认值"是最危险的 API 设计**——它让"忘记传参"变成一个不报错的错误。

> 这两个 bug 有一个共同点：**它们都发生在"接线处"**。系统的复杂度不在于每个模块内部，而在于模块之间怎么接。所以 `kb.load()` 这种"装配函数"值得被单独 review 一遍。

## 8. 本节小结

- 系统分**四条链路**：摄入造知识、查询找知识并生成、记忆记住人、API 对外服务；Web 与 CLI 共用 `kb.py`。
- **存储分工是一条铁律**：`knowledge_graph.json` 是唯一权威源，Neo4j 与 Milvus 是派生副本，`wiki/` 是人读视图——副本不一致就以 json 为准并重跑同步。
- 选型背后有一条原则：**会因静默失败破坏可信度的地方，宁可多一个依赖也要显式失败**。
- 配置只有 `app/config.py` 一处（旧文档的"根 config.py"说法已作废）；服务凭证集中在 `docker/.env`，且刻意"只填空缺、不覆盖、不展开 `$`"。
- 环境上有三个硬约束：`uv run python -m` 跑测试、`pymilvus>=2.5,<2.6`、ragas 版本组合不可动。

## 企业常见面试问答

**Q1：为什么不用一个数据库把所有东西都存了？**

> 因为四类数据的**访问形态完全不同**：图谱要按"关系"遍历（引用链、邻居扩展）→ 图数据库；向量要按"相似度"近邻检索 → 向量库；会话与画像要事务与唯一约束 → 关系库；而权威知识本体要**人能读、能 diff、能审计** → 文件。硬塞进一个库，等于让其中三类用最不擅长的方式工作。代价是要维护"权威源 → 副本"的同步，所以本项目把这条线写死：**json 是权威源，副本可随时重建**。

**Q2：权威源和副本不一致了怎么办？**

> 以 json 为准，重跑同步（`python -m app.ingest.sync_graph`）。系统刻意**不让检索侧去"发现"不一致**——`kb.load()` 只读 Neo4j，不会去比对 json，所以改了 json 就必须重跑，这是显式约定而不是自动兜底。同理，改了知识源（PDF/md）必须重跑 pipeline，因为 Milvus 里的向量不会自己发现知识库变了。历史上 `.npy` 缓存就是因为只按"文件是否存在"判定命中，导致语义召回长期静默失效——这正是我们放弃"自动发现"思路的原因。

**Q3：这套东西能离线/内网部署吗？**

> 能，而且大部分已经离线：bge-m3 是本地模型，Milvus/MySQL/Neo4j 都是本地容器，前端产物由 FastAPI 同源托管，唯一的外部依赖是 DashScope（qwen-max / qwen-turbo）。内网部署时知识构建、检索、记忆写入全部可用（本地向量编码零 API 成本），只有"意图识别"与"最终生成"需要换成内网模型：把 `app/config.py` 里的 `DASHSCOPE_BASE_URL` 指向兼容 OpenAI 协议的网关，并改 `LLM_MODEL` / `INTENT_MODEL` 即可。

**Q4：为什么要分 `app/config.py` 和 `docker/.env` 两个地方？**

> 按"**改的人不同**"分：`app/config.py` 放**代码级默认值**（路径常量、检索参数、模型名），随代码走、被 git 跟踪、可以 review；`docker/.env` 放**凭证**（账号密码、`JWT_SECRET`），因环境而异、不入库。两者的优先关系也刻意设计过：dotenv 用 `override=False` **只填空缺**，所以真实环境变量永远优先——CI/容器里可以继续用导出变量覆盖，不必改文件。
