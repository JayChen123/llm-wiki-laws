# 4.4 多跳检索（二）—— 反思式自主多跳

> 定位：把"固定跳数扩展"升级为"**由模型自己决定要不要继续深挖**"。这一节也是全课最容易被做坏的一处——我们会讲清楚它为什么**不能**替代图谱扩展。

本节目标：

1. 理解反思循环的定位：在基础扩展之上做**增量补取**，而不是另起一套检索；
2. 掌握**候选编号白名单**这一防幻觉机制；
3. 说清四个停止条件与 fail-closed 取向；
4. 用实测数据说明：为什么"纯反思替代图谱扩展"会让 recall 掉下来。

---

## 1. 从"固定扩展"到"自主决定"

4.3 的 BFS 扩展有一个特点：它是**无条件**的。不管问题是难是易、当前上下文够不够，都按固定的跳数与预算扩展一遍。

但真正该问的问题是：

> **"当前这堆条文，够不够答这个问题？"**

这个问题只有读得懂法条内容的模型能回答。于是就有了**反思循环**：

```
基础扩展（4.3）  ──►  反思循环（本节，≤ REFLECT_MAX_ROUNDS 轮）
  产出"基础上下文"       判"是否已充分 / 该补哪几条被引条文"
                               │
                               ▼
                    二者合并 = 最终上下文（reflect 是 bfs 的**超集**）
```

> 先把定位钉死：**reflect = 基础扩展 + 反思补取**。反思不是替代品，是"在已有基础上再补一层"。这个定位一旦搞错，效果会明显变差（见第 4 节）。

---

## 2. 反思循环怎么跑

### 2.1 候选从哪来：已收集条文的"被引条文"

```python
def _candidate_ids(self, collected: list[dict], seen: set[str]) -> list[str]:
    # 候选 = 已收集条文正文里引用到的、且尚未在上下文中的条文
```

实现上**复用 `graph_build.crossref_map()`**——和 3.2 建 crossref 边用的是**同一份实现**。这一点很重要：如果反思自己再写一套"怎么识别正文引用"的规则，两份规则迟早会漂移（一边认得多、一边认得少），而这种不一致极难排查。

### 2.2 候选以"编号白名单"交给模型

反思的 prompt 要求模型只输出 JSON：

```json
{"sufficient": true, "fetch": [2, 5], "reason": "已覆盖解除条件，但缺少补偿标准"}
```

关键在 `fetch` 里的**编号**：

| 机制 | 作用 |
|---|---|
| 候选以**编号列表**呈现给模型 | 模型只需回填编号，不需要复述条号（复述容易错） |
| **只接受候选集内的编号** | 越界编号一律丢弃 |
| 解析用 `_as_index()` + 边界校验 | 容错（模型可能回 `"第2条"`、`2`、`"2"` 等形态） |

这就是**防幻觉**：模型**不能凭空"要求"一条不存在的条文**——它只能在候选集合里挑。这一步把"模型的自由发挥"限制在了一个安全的动作空间内。

### 2.3 四个停止条件

```python
while rounds < self.max_rounds:
    candidates = self._candidate_ids(collected, seen)
    if not candidates:
        reasons.append("无可跟进的引用关系，停止")   # ← 不调 LLM，直接停
        break
    result = reflector.reflect(query, collected, candidates)
    reasons.append(f"[第{rounds + 1}轮] {result.reason}")
    if result.sufficient or not result.fetch_ids:
        break                                       # ← 模型判"够了"
    if 要取的条文均已在上下文中:
        reasons.append("反思要取的条文均已在上下文中，停止")
        break
    # 否则把这批条文取进上下文，继续下一轮
# 轮数用尽 → 自然退出（防失控）
```

| # | 停止条件 | 性质 |
|---|---|---|
| 1 | **无候选**（没有可跟进的引用关系） | **零成本停止**——不调用 LLM |
| 2 | 模型判 `sufficient`，或没给出要取的条文 | 正常收敛 |
| 3 | 要取的条文**都已经在上下文里** | 防"原地打转" |
| 4 | 达到 `REFLECT_MAX_ROUNDS`（默认 3） | **防失控** |

第 1 条是设计上最得意的一处：**全库只有 68/1465 个知识点正文里有可跟进的同法引用（97 处）**，所以绝大多数提问在第一轮就**直接停、一次 LLM 都不调**。这让"反思"这个听起来很贵的机制，在成本上几乎可以忽略。

### 2.4 fail-closed：异常即停

```python
REFLECT_MODEL = "qwen-turbo"     # 反思用轻量模型
REFLECT_MAX_ROUNDS = 3           # 轮数上限
REFLECT_TIMEOUT_S = 15           # 超时即停
```

反思的异常处理是**fail-closed**：超时、解析失败、模型报错——一律**停止继续检索**，保留已有的基础上下文。

这和 4.1 的意图识别（fail-open，异常放行）**方向相反**。为什么？因为两者的失败方向伤到的东西不同：

| 模块 | 异常时 | 理由 |
|---|---|---|
| 意图识别 | **放行**（fail-open） | 失败会**误伤用户**（正常法律问题被挡掉），代价高 |
| 反思检索 | **停止**（fail-closed） | 失败若继续，会**引入噪音条文**（甚至幻觉候选），污染上下文 |

> 判断 fail-open 还是 fail-closed，看的从来不是"哪个更安全"这种抽象说法，而是"**失败的方向会伤到谁**"。这是本课程反复出现的一条工程判断。

## 3. 两条链路可切换

```bash
RETRIEVAL_MODE=reflect   # 默认：基础扩展 + 反思补取
RETRIEVAL_MODE=bfs       # 对照：只做固定深度扩展（原方案）
```

保留 `bfs` 的意义在于**A/B**：任何对反思链路的改动（提示词、模型、轮数），都应该跑两遍 `eval --skip-ragas` 对比，确认没有回退。

## 4. 拒绝"纯反思"：一个掉分的实现

这是本课程里**最值得讲的一次失败**。

### 4.1 曾经的做法

最初实现反思时，我们把它做成了**替代方案**：

> 反思**完全替代**图谱扩展，候选**只有引用关系**（不走 sibling / semantic 邻居）。

听起来更"智能"——让模型决定一切，而不是用固定规则扩展。

### 4.2 实测结果

| 方案 | recall@1 | @3 | @5 | **@8** |
|---|---|---|---|---|
| 基础扩展（bfs） | 0.431 | 0.7119 | 0.8405 | **0.9262** |
| **纯反思**（替代扩展） | — | — | — | **0.8548** ❌ |

**recall@8 从 0.9262 掉到 0.8548。**

### 4.3 掉的是什么？

掉的全是 **sibling / semantic 邻居**带来的补充——它们**不属于"引用关系"**，所以在"纯反思"方案里根本进不了候选集。

这个结果说明一件重要的事：

> **引用关系只是图谱的一部分，不是全部。** 同章的结构邻居（sibling）、语义相近的条文（semantic）同样是"该进上下文"的信息，而它们**没有文本引用作为依据**——模型再怎么反思，也不会想到"去取同章的另一条"，因为那不是它能从正文里读出来的关系。

### 4.4 最终方案与结论

**reflect = 基础扩展 + 反思补取**（超集）。实测两条链路的 recall **完全一致**：

| 链路 | recall@1 | @3 | @5 | @8 |
|---|---|---|---|---|
| `bfs` | 0.431 | 0.7119 | 0.8405 | 0.9262 |
| `reflect` | 0.431 | 0.7119 | 0.8405 | 0.9262 |

> 也就是说：**反思在这个系统里的定位是"零成本的兜底增强"，而不是"主力召回手段"**。它不会让指标变差（是超集），在少数场景下能补到漏网的条文，而绝大多数提问它根本不触发。这是一个**诚实的定位**——比把它包装成"智能体自主检索"要准确得多。

## 5. 反思的实际增量（如实交代）

来自日志统计（`scripts/analyze_logs` + 单条日志）：

| 观察 | 数据 |
|---|---|
| 全库含可跟进引用的知识点 | **68 / 1465**（97 处引用） |
| 35 条评估用例中"无引用关系"零额外调用 | **19 条** |
| 各多 1 次 qwen-turbo 调用的 | 约 **20 条** |
| **真正补到条文的** | **只有 2 条**（共 +4 个知识点） |

为什么会这样？因为 **crossref 边的权重是 1.5（4.3）**——大部分被引条文**在基础扩展阶段就已经被带进上下文了**。反思的价值是"兜住漏网的那几条"。

**可选演进**（未验证）：把 BFS 的 crossref 权重调低，把引用链的活儿让给反思。这样反思的调用率与增量都会上升，但**总成本与效果是否更优没有验证过**——不要凭直觉改。

> 讲这一节时最该传达的态度：**一个看起来"高级"的机制（LLM 反思），实际收益可能很小；而它的代价（调用成本、延迟、不确定性）是实打实的。** 把它做进系统、量化它的收益、如实汇报——比把它吹成核心卖点更有价值。

---

## 6. 本节小结

- 反思的定位：**reflect = 基础扩展 + 反思补取**（bfs 的超集），是"零成本兜底增强"，不是主力召回。
- 候选 = **已收集条文的被引条文**，复用 `crossref_map()`（与建边同一份实现，避免规则漂移）。
- **防幻觉**：候选以**编号白名单**给出，只接受候选集内编号，越界丢弃。
- **四个停止条件**：无候选（**不调 LLM**）/ 模型判 sufficient / 要取的已都在上下文 / 达轮数上限。
- **fail-closed**（异常即停）——与意图识别的 fail-open 方向相反，判断依据是"失败伤到谁"。
- **拒绝纯反思**：曾用反思替代图谱扩展，recall@8 从 0.9262 掉到 **0.8548**，掉的全是 sibling/semantic 邻居——引用关系不等于图谱。
- 实测增量很小（97 处引用 / 仅 2 条用例真正补到条文），因为 crossref 权重 1.5 已在基础扩展阶段把大部分被引条文带进来了。

## 企业常见面试问答

**Q1：反思值不值一次 LLM 调用？**

> 在这个系统里，**值，但价值不在"提指标"**。实测两条链路 recall 完全一致（0.431/0.7119/0.8405/0.9262），反思真正补到条文的只有 2/35 条用例。它的价值有三点：① **零成本停止**——全库只有 68/1465 个知识点有可跟进引用，绝大多数提问在"无候选"这一步就停了，**一次 LLM 都不调**；② **兜底**——它是超集，不会让效果变差，少数漏网条文能被捞回来；③ **可解释**——日志里有 `reflect_fetched`（补了哪几条、第几轮）与 `reflect.reasons`（为什么停），排查"某条法条为什么没进上下文"时，能明确区分是"检索没命中""扩展没带出"还是"反思没补到"。**诚实的结论是：它是个便宜的好保险，不是核心卖点。**

**Q2：怎么防反思幻觉？**

> 关键在**动作空间的设计**：反思不做"自由生成"，只做**选择题**。我们把候选条文以**编号列表**呈现给模型，要求它回填编号；解析时**只接受候选集内的编号，越界一律丢弃**。所以模型即使"想"取一条不存在的条文，也做不到——它没有"新增条文"这个动作。另外两道保险：① 候选本身来自**正文解析出的真实引用**（不是模型想象的）；② 反思失败时 **fail-closed**（停），不会把可疑内容放进上下文。这个思路可以推广：**凡是让 LLM 参与决策的地方，都尽量把它的输出约束成"在给定选项里选"，而不是"自由生成"。**

**Q3：停止条件怎么设计的？**

> 四个，按代价从低到高：① **无候选**——从正文里解析不出可跟进的引用，直接停（**不调 LLM**，这是最省的一档）；② **模型判 sufficient 或没给出要取的条文**——正常收敛；③ **要取的都已经在上下文里**——防原地打转（否则会重复取同一条）；④ **达 `REFLECT_MAX_ROUNDS`（3）**——防失控的硬上限。四个之外还有超时（15s）即停。设计思路上有一条：**先便宜后昂贵**——能靠本地计算判断的（有无候选、是否已收集）绝不去问模型；能让模型一次说完的，不要拆成多轮。这样平均成本才能压得住。

**Q4：为什么不用反思替代图谱扩展？更"智能"啊。**

> 我们试过，**掉分**：recall@8 从 0.9262 掉到 0.8548。原因是掉的全是 **sibling / semantic 邻居**——它们不属于"引用关系"，在"纯反思"方案里进不了候选集。而这类邻居是检索补不上的补充信息（4.3 讲过：多跳补的是"结构相关但内容不像"的条文）。**模型再怎么反思，也不会想到去取"同章的另一条"**，因为那不是它能从正文里读出来的关系——它只能看到文本里的引用。这件事的教训是：**LLM 的"自主"有边界，它的知识来自你给它的上下文**。把结构化关系（图谱）让给确定性算法、把"够不够"这种语义判断交给模型，是更合理的分工。
